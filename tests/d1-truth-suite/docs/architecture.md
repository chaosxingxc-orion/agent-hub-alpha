# D1 真值套件 · 架构

## 1. 分层

```
被测面      gates/ 四代闸（词法检测器，单文件 Python，零依赖）
判定层      d1-runner-full.py：语料分段 → 逐段隔离喂闸 → 声明级解析 → 混淆矩阵
仪器层      probes/d1_probes.py 矩阵自检；run-mutants / r3-audit-battery 两台行为电池
证据层      results/ JSON＋sha256 校验＋审计收据；provenance 桥哈希
```

判定单元：段级二值（该段是否出现 ≥1 计数声明 FAIL）承载记分；声明级明细
（行号＋规则档＋token 逐字）承载分诊。规则档：`COUNTING/<单位词>`、`TRIPLE`、
`PROGRESS`、`REDCOUNT`、`OTHER`、兜底 `COUNTING/?`（哨兵盯漂移）。

## 2. 设计三律（本套件之所以可信的根）

**注记剥离**：语料段内的"（事实：…）"真值批注行不喂闸。早期实测证明批注行会泄漏成
假阳性判定（FN 被批注数字翻成"命中"），剥离后三代分差全部重排——评测语料的
元数据必须在喂仪器前剥离，并记录 dropped 计数作收据。

**声明级判定**：段级"命中/放行"会藏住命中点错位——某事件本体的声明与闸实际命中的
token 可以完全不同。每条 finding 落到 (行, 规则, token)，归属不调用复刻正则：
importlib 载入被测闸模块、用它自己的 `find_claim/TRIPLE/PROGRESS/REDCOUNT/UNITS`
做判定（仪器侧与被测侧共享真源，防镜像漂移）。

**判别式对照段**：合法段从被测对象源码定死期望。控制段 D2 携带 `ls`/`find` 反引号
证据命令——对未修复血统必然误报（白名单分支缺失该二命令的实证在闸源码内），对修复
血统必然放行——该控制段同时打出"病活着"与"病已修"的鉴别面。

## 3. 真源治理（闸体自身的法）

- **P-Ⅰ 单源律**：同一词法事实不得存在第二手抄面。CMD 证据命令表派生双分支（行首形
  与反引号形共享 `_CMD_TOOLS` 元组）；PROGRESS 动词表派生双析取；UNITS 从 COUNTING
  模式自身的交替组派生——镜像分裂在结构上不可表达。
- **判别钉族**：新语义必带双向钉（命中形 True ＋ 误报守卫形 False，逐成员穷举）。
  census 四轴常验：单位钉、派生组钉、模式覆盖钉。
- **载体家法**：零载体的逃逸形（复合色名前缀、小数尾读数、时长误读形——逐形清单在
  闸内注释⑤与 `docs/receipts/attack2.md`）注册挂账、不投机扩展；
  扩展以真载体＋逐成员钉为入籍条件。
- **语义半径**：注释/文档声明的强度不得超过其证据宽度；跨面声明必须限定面
  （段隔离面与整档面的放行语义不同源，禁止互引——此律由"声明-实态差"的数轮复发代价换来）。

## 4. 真载体面

套件面之外，闸对两份战役文档做 e2e 记分（包内以别名 truth-doc-A/B 记钉值，原文不发）：
四代命中数冻结为钉——v2.7.2 在 A 文档面 26 hits、B 文档面 16 hits，set-diff 判据锁死
"新增恰等读数行、原命中零损失"。
A 文档上 v2.6 血统的洪峰属单位集病（另案）；truth-doc-A 的 `ls` 反引号
载体行是白名单病真载体：四代判定 True/True/False/False 与血统修复史逐一对齐
（复核方式见 MANIFEST 与 provenance 桥；战役档案环境跑仪器即自动对该面跑满）。

## 5. 打码与可复核性

出站包的 results/ 为路径/文档名打码拷贝（判定、声明、计数、文件内容哈希不动），打码后
校验和重算；原始哈希链与变体说明（v2.7.1 包内副本的私有仓名注释通用化、公仓 v2.6 外部
锚待补）逐条记录在 `results/provenance.json` 与 `MANIFEST.md`——哈希作桥。
打码不影响复现：克隆后重跑仪器即在本地生成同判定结果。
