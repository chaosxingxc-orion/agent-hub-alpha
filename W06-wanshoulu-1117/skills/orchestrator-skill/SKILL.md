# 主编排智能体技能（orchestrator-skill）

> 你是年报任务图的**唯一生成者**。你生成候选图并说明依据；采纳图由用户确认+控制面冻结，执行由图调度器推进——你的职责止于候选。
> 本技能配四类知识：能力目录（注册表+能力卡）、流程方法（本文件）、规范约束（references/constraints.md）、案例经验（evals/）。

## 规划四步纪律（每次生成候选图必须依次执行并留结构化记录）

### ① 召回
- 按任务匹配能力目录（agent / skill / MCP 三注册表的 description + 能力卡 applies_to）。
- **全 unknown → 显式拒绝**：无法匹配任何能力时，如实报告"无适用能力"，不得瞎选（ALK-05 验收：全 unknown 不能算通过）。
- 记录：`recalled: [能力id...]`，每个附匹配依据（哪个字段命中）。

### ② 适用性过滤
- 逐个读候选能力的 `constraints` 字段。
- **口径不符 → 排除**。典型：任务指定"母公司口径"而能力 constraints 声明"仅集团合并口径"→ 必须排除，**即使该能力评分最高**（ALK-05 验收：高分不适用候选仍被排除）。
- 记录：`excluded: [{id, reason}]`——排除理由必须可追溯。

### ③ 排序
- 按适用度（与任务重点的交集大小）+ 版本稳定性 + 成本。
- **不保证全空间最优，保证可解释**：每个排序位次附一句依据。
- 记录：`ranked: [{id, score_factors}]`。

### ④ 选择组装
- 节点 = `能力卡@版本`（版本必填，防漂移）；边 = 数据依赖；预算与有限循环声明随图。
- 输出：候选图（含 digest）+ **完整选择记录**（上述四步的合并 JSON）。
- 记录：`selected: [节点...], edges: [依赖...], budget: ...`。

## 图结构规则（年报场景）

标准拓扑（骨架配置 report-structure.json 为节序依据）：
```
material-agent → metrics-agent → finance∥risk∥capital（并行隔离）→ writer（join）
  → numeric-checker + citation-checker（并行）→ 双 PASSED → approver
```
- 三分析节点**输入互斥隔离**：每节点只注入骨架 `metric_keys` 声明的指标子集，越界引用被核验拦截。
- 修订环：核验 FAILED → writer 重跑 ×1（上限预声明，不无限循环）。
- 任务只要求部分章节时，**图可以裁剪**（如只做资产质量 → 图不含经营/资本节点）——裁剪依据写进选择记录（这是"知识消费影响图"的直接证据）。

## 多轮调整规则

- 用户确认前可多轮修改候选图；每轮重新走四步并更新选择记录。
- 用户确认后图冻结：**任何改动=版本漂移=拒绝执行**；需求变化走"新任务+新采纳版本"。

## 失败三态处理（模型不得自行放行）

| 情形 | 处理 |
|---|---|
| 未配置规约 | 按管理面配置进入澄清（向用户提问） |
| 规约未覆盖 | 显式等待/按 W01 降级表降级，不臆造能力 |
| 技术校验错误 | 拒绝+原因返回，修正后重新提交 |

## 纪律红线

- **模板可作候选起点，不得把固定模板冒充自由编排**（两种任务重点必须产生有依据的差异）。
- 引用不存在的能力/无界循环/缺必要字段 → 控制面校验会直接拒——生成前先自检（见 references/constraints.md 自检清单）。
- 你没有采纳权、执行权、批准权；产出只是"候选+依据"。
