1 · 对比结论

变化集中在专业 Agent 的部署与调用边界，以及远端结果的可靠控制。

原型已有中枢规划、用户确认、真实 Graph 并行、Loop Forest 和节点结果复用。本轮将五个专业节点接到三个独立 Runtime，由 Gateway DIRECT 调用、RDC 发现；Go 保存派发意图、远端关联与正式结果，页面展示这些持久事实。

3 · 当前架构

feat/issue16-agent-bus · 4d5d1b8

资料、分析与写作改为独立 Runtime，Graph 通过窄适配器接入 Gateway。关联方 Loop Forest 和风险判断保留在宿主内。

保留增强新增

蓝线：执行与 Agent 调用　橙线：确认、控制与正式结果提交　绿虚线：能力发现与路由　灰虚线：记录与工具关联

Runtime 产物经 Gateway 返回 Java；适配器校验后提交 Go，持久化成功才向 Graph 返回正式结果。RDC 的 PostgreSQL 不存储 Go 节点结果；三类服务通过部署发现接入 RDC。

复用约束得到保留：继续使用 openJiuwen、WorkSwarm、Agent Bus、Loop Forest。新代码集中于远程成员适配、专业角色封装、控制缺口和场景配置。

5 · 当前调用与恢复

  1. 发现并固定能力从受控目录读取真实 RDC 卡片，计划采纳绑定能力与契约版本；派发前再次核对。
  2. 先保存派发意图记录节点执行身份、输入摘要与原请求标识。必需记录保存失败时停止派发。
  3. 经 DIRECT 调用Java 调用 Gateway，Gateway 解析可信路由。Runtime 按节点凭据取得输入并执行。
  4. 关联原任务保存远端 task / context；查询沿用原任务。HTTP 200 中的协议错误仍保持错误或未决。
  5. 提交正式结果校验身份、输入摘要、尝试与产物；Go 落盘成功，Graph 才允许依赖节点消费结果。
  6. 按已有事实恢复已完成节点读取正式产物；有任务号则查询原任务；恢复信息不足时保留未决并等待人工核对。

宿主重启

恢复读取原采纳图；实验 R11 验证已完成节点复用，产物标识和摘要不变，已完成远端节点模型调用事件集合不增加。

Gateway / Runtime 重启

当前上游任务归属索引和默认任务存储在内存中。R15 / R16 验证任务丢失后保持未决，不自动生成第二份调用。

6 · 边界与依据

实际完成范围：两版均为授信模拟场景。公开年报材料、指标与引用核验、报告验收导出、命令级去重、暂停、跨任务资料复用和反馈仍需补齐。#6 知识服务是可选增强，不是启动依赖。

页面证据的口径

RDC 候选是发现时的快照；实际执行实例未采集。Gateway 时刻来自 Java 宿主观测。历史缺失数据不补写，模型尝试数不等于供应商账单。
